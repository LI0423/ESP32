# Desktop Companion / DeskPal

ESP32-S3 桌面电子宠物：240×240 单屏像素角色、实时生理消耗、照护与成长、NVS 持久化、WiFi 网络校时和 OTA。番茄钟保留为获取照护资源与经验的辅助系统。

## 当前功能

- 无实体按键、旋转编码器、触摸或音频；通过 HTTPS 管理页和 USB 串口交互
- 板端独立运行，不依赖 PC Agent
- 宠物属性：饱食度、健康、心情、清洁度、食物、药品、经验、年龄与成长阶段
- 照护动作：喂食、用药、陪玩、清洁；动作有冷却时间，食物和药品为限量库存
- 专注完成奖励：每轮 `+20 XP`、`+1 食物`；每 4 轮额外 `+1 药品`
- 忽视会导致可恢复的生病，不会死亡或逃跑；健康最低为 10
- 时区默认 `CST-8`；本地 **08:00–22:00** 为工作时段，自动循环：专注 25 分钟 → 庆祝约 8 秒 → 休息 5 分钟 → 下一轮
- **22:00–次日 08:00** 自动待命：停止计时循环、不增加完成轮次、屏幕临时降亮；宠物按夜间睡眠速度消耗饱食度
- 屏幕显示成长阶段、饱食/健康/心情/清洁、今日专注进度、连续天数、剩余时间和在线状态
- 角色左上角以 1Hz 闪烁的像素徽章表达需求：**米饭碗**表示饥饿/饥饿病，**药丸**表示药物可治的生病；两者互斥，生病优先；状态行不再显示病因文字
- 时间未同步/无效时，不按错误墙钟切换待命、成长或执行照护动作
- WiFi 离线时计时继续；网络状态仅体现在右上角在线指示点
- 当前阶段、日程、目标统计和宠物状态保存在 NVS；属性变化或阶段切换时写入，不每秒擦写
- WiFi 使用 AP+STA，错误凭据不会移除配网 AP
- mDNS 地址：`deskpal.local`

## 宠物规则

| 行为 | 效果 | 冷却 |
| --- | --- | --- |
| 喂食 | 饱食 `+35`、心情 `+1`、`+5 XP`，消耗 1 食物 | 10 分钟 |
| 用药 | 健康 `+45`、心情 `+5`、`+10 XP`，消耗 1 药品；仅生病时可用 | 6 小时 |
| 陪玩 | 心情 `+15`、饱食 `-2`、`+8 XP`；生病时不可用 | 30 分钟 |
| 清洁 | 清洁 `+50`、心情 `+3`、`+5 XP` | 1 小时 |

饱食度超过 90 时继续喂食会吃撑：健康 `-10`、心情 `-5`；2 小时内吃撑 2 次会生病。

清醒时饱食度每小时 `-4`，夜间睡眠时每小时 `-2`。饱食度为 0 持续 6 小时会因饥饿生病；清洁度低于 20 持续 12 小时会因脏污生病。药品可以治病，但不会代替喂食或清洁；脏污生病也可通过清洁恢复。

离线生理模拟最多补算 48 小时，年龄按真实本地日界增长。短期断网不会造成死亡或库存清空。

## 成长阶段

成长必须同时满足年龄和累计经验：

| 阶段 | 年龄 | 累计 XP |
| --- | ---: | ---: |
| 幼年 Baby | 0 天 | 0 |
| 童年 Child | 1 天 | 100 |
| 青年 Teen | 3 天 | 300 |
| 成年 Adult | 7 天 | 600 |

Grok 版四阶段素材已接入索引精灵生成器：休息/待命时显示 Baby / Child / Teen / Adult 外观，喂食、用药、陪玩、清洁时显示对应动作素材。专注、庆祝、饥饿和生病继续复用原有表情。当前 8 张新素材共约 128KB 索引数据，先嵌入 app；完整表情包后续再迁移到 6MB `assets` 分区。

## 重启恢复策略（stale-save gap）

NVS 的阶段快照只在阶段切换等事件时写入，`saved_epoch` 不是精确断电时刻，也不能据此判断用户是否离开。

| 条件 | 计时器行为 |
| --- | --- |
| 时间未同步/无效 | 安全恢复已保存阶段与剩余秒数；不按墙钟切入待命、不快进、不虚增轮次 |
| 距上次保存 **< 约 30 分钟** | 按保存的阶段剩余时间恢复；再结合工作时段规则处理待命 |
| 距上次保存 **≥ 约 30 分钟**，且在工作时段 | 不快进；从一轮全新专注开始，保留当日已统计轮次 |
| 距上次保存 **≥ 约 30 分钟**，且非工作时段 | 不快进；进入待命 |

宠物独立按 `last_update_epoch` 补算生理消耗，最多 48 小时；不会把旧版“未达今日目标”直接迁移成宠物生病。

## NVS schema v2

- 计时器记录保持原有版本化格式
- 宠物记录使用 schema v2 版本字节和定长、显式小端编码的 55 字节 `pet_state` 负载
- 完整 blob 为 56 字节，只占三个 BLOB_DATA 跨度项和一个 blob 索引项；阶段与小数累积时间不持久化，加载时重建
- NVS 空间不足时先清理已废弃的 DesktopStatusPad 键，再重试宠物记录写入
- 读取时校验长度、字段范围、阶段/经验关系、生病原因和时间戳
- 旧设备没有宠物记录时，从旧计时器迁移累计专注轮次为经验和 `focus_count`，使用默认初始库存
- 旧 `missed_day` 只保留为今日目标统计，不再驱动宠物生病

## 构建与烧录

使用 ESP-IDF v5.5.4。先导出本机的 IDF 环境：

```bash
. "$IDF_PATH/export.sh"
```

`main/admin_cert.h` 内嵌管理 HTTPS 的证书和私钥，已在 `.gitignore` 中，干净检出里没有这个文件。构建前在本机生成，不要把该头文件或私钥提交到 git：

```bash
bash tools/gen_admin_cert.sh
```

脚本用 OpenSSL 生成一张 CN 为 `deskpal.local` 的自签名证书（SAN 包含 `deskpal.local` 和配网地址 `192.168.4.1`），并写入 `main/admin_cert.h`。再次运行会替换本机证书。

```bash
idf.py set-target esp32s3
idf.py build
```

`sdkconfig` 同样被忽略。没有私有 `sdkconfig` 时，`sdkconfig.defaults` 会指定 ESP32-S3、16MB Flash、自定义 `partitions.csv`、八线 PSRAM 和尺寸优化。Secure Boot 与 Flash Encryption 保持关闭。

烧录串口用环境变量 `ESPPORT`：

```bash
export ESPPORT=/dev/cu.usbmodem*
idf.py flash
idf.py monitor
```

应用输出为 `build/desktop_companion.bin`。本轮构建大小 **1,301,184 bytes（约 1.241MB）**，1.5MB OTA 槽剩余约 **17.3%**（271,680 bytes）。

## 测试

```bash
bash tools/run_tests.sh
DESKPAL_ADMIN_TOKEN=<串口日志中的令牌> python tools/http_smoke_test.py
```

主机测试覆盖：

- 专注/庆祝/休息循环、工作时段边界、跨午夜手动待命和重启恢复
- 今日日界、目标、连续天数与旧版 vitality 回归
- 清醒/睡眠消耗、饥饿与脏污生病、吃撑、药品与清洁恢复
- 动作冷却、限量库存、专注奖励、年龄 + XP 成长和 48 小时离线上限
- 串口照护命令解析
- 14 张索引精灵与 2 枚 HUD 徽章（药丸、米饭碗）的数据/调色板访问与生成文件一致性

HTTPS 证书/私钥长度已改为传入含结尾 NUL 的完整数组大小（`sizeof(...)`），与 ESP-IDF v5.5.4 和 mbedTLS 的 PEM 解析要求一致；原 `sizeof(...)-1` 会丢掉 NUL 并导致启动失败。网页照护 API 已随固件构建，但本轮未跑 `http_smoke_test.py`，网页端联调仍待验证。

## 首次配网

连接 `DeskPal-Setup`，默认密码 `deskpal1`，打开：

```text
https://192.168.4.1
```

板端使用自签名证书，浏览器首次会提示不受信任。生产部署应替换为自己的受信任证书。已有 WiFi 凭据会从旧项目的 NVS 命名空间自动继承。

首次启动会生成随机管理令牌并输出到串口日志。如果错过日志，可发送 `token` 本地读取；令牌只保存在板端 NVS，网络 API 不会返回它。

## USB 串口命令

每行一条，回车结束；效果与网页相同并写入 NVS：

```text
goal <1-99>   设置今日目标，例如 goal 6
focus         开始新一轮专注
standby       今晚先待命，直到下一个本地 08:00
feed          喂食
medicine      用药
play          陪玩
clean         清洁
status        打印一行状态 JSON（包含 pet 对象）
token         打印管理令牌
```

`goal` 只接受 1–99 的整数；照护命令不接受参数。无效输入不会改变状态。

## 网页 API

管理页提供宠物状态摘要和四个照护按钮，以及 WiFi、亮度、今日目标、OTA、开始专注和待命操作。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/status` | 计时器、宠物、网络和 OTA 状态 |
| POST | `/api/pet/feed` | 喂食 |
| POST | `/api/pet/medicine` | 用药 |
| POST | `/api/pet/play` | 陪玩 |
| POST | `/api/pet/clean` | 清洁 |
| POST | `/api/timer/focus` | 开始新一轮专注 |
| POST | `/api/timer/standby` | 待命到下一个 08:00 |

所有修改、照护、重启、OTA 与计时操作都需要 `Authorization: Bearer <token>`。照护请求体可省略或传 `{}`。冷却、缺物品、未生病、生病过重等拒绝条件返回 HTTP 409 和 `error`；成功返回 `applied`、`result` 与最新 `pet` 状态。

## OTA 与安全

生产固件默认只接受 HTTPS OTA。本地开发测试如需 HTTP OTA，在 menuconfig 启用 `COMPANION_OTA_ALLOW_HTTP`，然后运行：

```bash
DESKPAL_ADMIN_TOKEN=<token> python tools/lan_ota_test.py \
  --device-ip <board-ip> --allow-http
```

OTA 支持取消、总超时和无进展超时。Secure Boot V2 与 Flash Encryption 属于不可逆 eFuse 配置，当前未自动启用；生产部署前应单独规划签名密钥并开启。

## 时间与持久化

- 时区默认 `CST-8`，可在 menuconfig 修改
- NTP 默认 `ntp.aliyun.com`，备用 `162.159.200.1`
- SNTP 初始化失败会每 5 秒重试
- 计时器阶段、日程、目标统计和宠物属性在事件变化时写入 NVS
- 宠物在有效网络时间下补算离线消耗；无效时间只保留状态，不执行照护动作
